# RK3588 bililive-go 实施与验证记录

验证日期：2026-10-09。正式交付目录：`/opt/DockerDate/bililive-go`，正式地址：[管理页面](http://192.168.10.62:8084)。开发目录只用于源码、编译和隔离调试，生产容器不挂载开发目录。

## 一、最终配置

- ARM64 应用发布版：`rk3588-20261009`，上游源码基线 `230e24d17c865ebadb86c74781913ec325f07f28`，适配补丁与新增源码归档保留，未提交到 Git。
- MPP、RGA、libass、中文字体与专用 FFmpeg/ffprobe 均在镜像内。
- 默认 `hevc_rkmpp`、目标码率 4M、无弹幕也压缩；有 ASS 时与烧录合并一次编码。
- 原视频和 ASS 均保留；只允许硬解失败软件解码回退，不自动软件编码。
- 不缩放，音轨流复制，后处理并发 1；不绑定 CPU 亲和性。
- UID/GID 1000:1000，附加 video/render 组；无全特权，capabilities 全删除，no-new-privileges。
- 映射 MPP/RGA/DMA heap 和 DRM 分配器；不映射 NPU。
- MPP 从只读挂载的 `/opt/rk3588/device-tree/compatible` 识别 SoC，使用容器用户态库小补丁，不改内核或宿主库。
- 保留原外盘录像绑定，未修改或集成 USB 守护。
- 默认关闭原来的 FLV 原地修复：该旧功能会替换源文件，不符合本轮验证期间保留原录像的安全要求。用户有需要可手动开启，行为与压缩阶段不同，不能承诺修复前原件自动保留。
- 自更新、自动下载关闭，镜像内环境变量禁止应用在线替换及普通 FFmpeg 自动下载。

## 三、容器硬件短测

全部使用隔离合成素材，不访问历史录像。以非 root 用户、最小设备权限执行：

1. H.264 MPP 编码 720p30、4 秒，带 48kHz AAC 音轨：成功。
2. MPP H.264 硬解 DRM prime → H.265 MPP 编码：成功。
3. MPP 硬解 → hwdownload → libass 中文字幕 → H.265 MPP 编码：成功，中文字体可见。
4. MPP 硬解 → RGA 缩放 1280×720 到 640×360 → H.265 MPP 编码：成功。
5. MPP 硬解 → RGA → `mjpeg_rkmpp` JPEG 封面：成功。
6. 压缩、烧录和缩放产物均完成整个视频的软件解码校验，ffprobe 确认 HEVC、目标分辨率与音轨。
7. 实际 H.264 High10（yuv420p10le）输入 → MPP 硬解 → RGA 转 NV12 → 中文 ASS → H.265：成功，任务记录没有软件解码重试。

中文合成画面与封面验证时曾保存在正式交付 `verification/`，后续按用户要求删除。字幕绘制仍是 CPU/libass，不宣称全链纯硬件。

## 四、应用接口与安全回归

- `hardware/status` 首次真实编解码自检通过，`ready=true`、`warnings=[]`。
- `batch-burn` 实际烧录+压缩；`batch-compress` 无 ASS 正常处理。
- 同一请求重复路径只入队一次；`../` 越权、软链接指向输出目录外均拒绝。
- 损坏输入任务失败，源文件保留，不产生正式输出。
- 已有输出不被覆盖，新输出追加序号，产物权限 0644。
- 运行中取消任务保留源和 ASS，删除独占临时输出。
- 取消曾暴露“失败能力探测污染缓存”问题；已修复为完整成功才缓存，取消/失败刷新不覆盖有效缓存，最终镜像紧接正常任务复测成功。
- 房间首次只修改 rk3588 曾暴露其他后处理字段被零值覆盖；已修复以当前有效全局/平台配置为基，旧显式覆盖不清除，`rk3588:null` 删除冗余覆盖恢复继承，真实 API 回归通过。
- 非法房间/平台配置写入前校验，不会失败后半写在线配置；房间专用 FFmpeg 路径贯通到后处理任务。
- 自检按 FFmpeg/编码器串行合并，并有 15 秒最小重测间隔。状态列表是能力探测，真实自检也只证明该样本，不能保证所有实际录像均支持。
